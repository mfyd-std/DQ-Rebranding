## How the mapping below was verified

The bundle was restored into a throwaway clone and filtered again with the same
path list. That independent run produced `bf8ccc9ed5920691eac3cb344d55cfcada975adc`
for the merge of pull request #4, identical to the rewritten commit in this
repository, and the same tree hash `91162290c8f90432ab2d58e2a986c42098e4171b`.
The filtering is deterministic, so the mapping from that run applies here.

## Deploying after a force push

Netlify did not start a build for the force-pushed commit. Production kept
serving the deploy built from `252d1784` until a normal push to `main` arrived.
If this ever happens again, follow the force push with a normal commit or trigger
a deploy manually, then confirm `commit_ref` on the deploy matches
`git rev-parse origin/main`. Do not assume the push rebuilt production.

## If you have an old clone

Your clone no longer matches the remote. Either re-clone, or:

```bash
git fetch origin
git reset --hard origin/main
git reflog expire --expire=now --all
git gc --prune=now --aggressive
```
